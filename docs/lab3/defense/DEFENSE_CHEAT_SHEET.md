## 2. ТОП-10 каверзных вопросов преподавателя и идеальные ответы

### ❓ Вопрос 1: Почему в подсети /24 доступен 251 IP-адрес, а не 256?
**Ответ:**  
В сети `/24` физически $2^8 = 256$ адресов. В отличие от традиционных сетей, где резервируются только 2 адреса (Network и Broadcast), **AWS резервирует ровно 5 адресов**:
1. `.0` — Network address (сетевой адрес).
2. `.1` — VPC Router (внутренний шлюз подсети).
3. `.2` — AmazonProvidedDNS (виртуальный DNS-резолвер Route 53).
4. `.3` — Зарезервирован AWS для будущего использования.
5. `.255` — Broadcast address (широковещательный адрес; в VPC широковещание не поддерживается, но адрес недоступен).  
Итого: $256 - 5 = 251$ адрес.

### ❓ Вопрос 2: Что именно делает подсеть публичной? Почему недостаточно просто назвать её "public"?
**Ответ:**  
Имя подсети — это просто текстовый тег (`Tag: Name`). Подсеть становится публичной **только при выполнении двух условий**:
1. Таблица маршрутов подсети содержит маршрут по умолчанию `0.0.0.0/0`, указывающий на **Internet Gateway (`igw-xxx`)**.
2. Экземпляры в подсети имеют назначенные публичные IPv4-адреса (Public IP или Elastic IP).  
Если маршрута в IGW нет, подсеть является приватной, как бы она ни называлась.

### ❓ Вопрос 3: В чём разница между Security Group и Network ACL?
**Ответ:**
| Параметр | Security Group | Network ACL |
| :--- | :--- | :--- |
| **Уровень действия** | Сетевой адаптер инстанса (ENI) | Граница подсети (Subnet boundary) |
| **Тип фильтрации** | **Stateful** (запоминает состояние сессии) | **Stateless** (каждый пакет проверяется отдельно) |
| **Правила** | Только разрешающие (`Allow`) | И разрешающие (`Allow`), и запрещающие (`Deny`) |
| **Порядок обработки** | Проверяются все правила; если хотя бы одно разрешает — трафик проходит | Проверяются строго по номерам правил по возрастанию до первого совпадения |
| **Обратный трафик** | Ответный трафик пропускается автоматически | Требуется явное разрешение обратного диапазона портов (Ephemeral ports 1024-65535) |

---

### ❓ Вопрос 4: Зачем мы ставили запрещающее правило в Network ACL с номером 90? Что было бы при номере 110?
**Ответ:**  
Правила в Network ACL обрабатываются сверху вниз по номеру. Стандартное правило `100` разрешает весь входящий трафик (`Rule 100: 0.0.0.0/0 Allow`).  
- Правило `90` с действием `Deny` проверяется **раньше**, поэтому трафик с домашнего IP блокируется сразу.
- Если бы мы поставили номер `110`, пакет сначала совпал бы с правилом `100 (Allow)` и был бы пропущен. Правило 110 никогда бы не выполнилось.

### ❓ Вопрос 5: Что такое Jump Host (Bastion) и как работает механизм `ProxyJump`?
**Ответ:**  
Бастион — минималистичный защищённый сервер в публичной подсети, единственный имеющий открытый порт SSH наружу (и только для доверенного IP администратора).  
Команда `ssh app` благодаря директиве `ProxyJump bastion` в `~/.ssh/config` запускает прозрачный SSH-туннель: локальный SSH-клиент сначала открывает защищённый сокет к бастиону, а через него инициирует сессию к приватному IP `10.28.0.142`. При этом приватный ключ с локального Mac **никогда не передаётся на бастион**, что защищает от перехвата ключей.

### ❓ Вопрос 6: Почему Elastic IP нужен `app-server`, но не нужен `bastion`? Сколько он стоит при остановленном сервере?
**Ответ:**
1. `app-server` обслуживает пользователей и внешние веб-запросы. Смена IP сломает доступ и DNS.
2. `bastion` нужен только администратору. В случае смены динамического IP при рестарте администратору достаточно поменять одну строчку в файле `~/.ssh/config`.
3. **Тарификация:** Если Elastic IP привязан к работающему серверу — он **бесплатен** (1 адрес). Но пока сервер остановлен (`Stopped`) или если адрес не привязан, AWS берет **$0.005 в час (~$3.65 в месяц)**, чтобы предотвратить дефицит свободных адресов IPv4.

### ❓ Вопрос 7: Зачем база данных спрятана в приватную подсеть и как работает концепция Defense in Depth (эшелонированная защита)?
**Ответ:**  
База защищена на трёх независимых рубежах:
1. **L3 (Сеть VPC):** У `db-server` нет публичного IP, а в таблице маршрутов подсети `private-a` нет шлюза в интернет. База физически недостижима из внешнего мира (RFC 1918).
2. **L4 (Виртуальный файрвол):** Security Group `db-sg` разрешает входящие пакеты на порт 5432 строго от группы `web-sg` (только от сервера приложений). Трафик с бастиона или других хостов отбрасывается гипервизором.
3. **L7 (Уровень СУБД):** Конфиг `pg_hba.conf` пускает только пользователя `timecapsule` в базу `timecapsule` с подсети `10.28.0.0/24` по шифрованному протоколу `scram-sha-256` с надёжным паролем.  
*Если злоумышленник взломает один уровень (например, получит шелл на веб-сервере), остальные рубежи не позволят легко захватить базу данных.*

### ❓ Вопрос 8: Как работает приватная зона Route 53 (`timecapsule.internal`)? Почему `dig` резолвит имя на сервере, но не на вашем компьютере?
**Ответ:**  
Приватная зона Route 53 ассоциирована исключительно с нашей VPC (`vpc-083255eb804055334`).  
- Запросы от `app-server` уходят на виртуальный резолвер VPC `10.28.0.2` (AmazonProvidedDNS), который знает приватную зону и возвращает `10.28.10.228`.
- Домашний компьютер опрашивает публичные DNS провайдера/Google (8.8.8.8), которые ничего не знают про домен `.internal` и возвращают `SERVFAIL`.

### ❓ Вопрос 9: Зачем нужен временный (эфемерный) NAT Gateway, а не постоянный?
**Ответ:**  
Постоянный NAT Gateway в AWS стоит ~$0.045 в час (~$38 в месяц) + трафик, даже если через него ничего не передаётся. Для базы данных интернет нужен исключительно во время регламентных обновлений (`sudo dnf update`).  
Мы использовали модель **On-Demand NAT**: скриптами `nat-up.sh` / `nat-down.sh` шлюз создаётся на 5–10 минут для установки пакетов и сразу уничтожается. Затраты составляют меньше 1 цента за сессию обслуживания.

### ❓ Вопрос 10: Что произошло при остановке базы данных в тесте на отказ (Failover)? Изменился ли её приватный IP?
**Ответ:**  
- При остановке службы СУБД эндпоинт `/health` вернул HTTP 500 и JSON `{"status":"error","db":"error"}` из-за отказа в TCP-соединении к порту 5432.
- После запуска службы приложение самовосстановилось (`self-recovery`) без перезапуска Nginx или PHP-FPM.
- Приватный IP `10.28.10.228` **не изменился**: в Amazon VPC приватные IP-адреса жестко закреплены за сетевым интерфейсом (ENI) инстанса на весь его жизненный цикл.
